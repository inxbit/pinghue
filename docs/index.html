A host that blips once stays intermittent until you reset it. A maintenance-window report should reflect everything that happened, not only the final moments.

Close the window with a report.

$ pinghue -f hosts.txt --duration 180 --output maintenance.json{  "schema_version": 1,  "pinghue_version": "5.0.0",  "run": { "host": "local", "exit_reason": "deadline", … },  "targets": [    { "target": "db-primary", "status": "intermittent",      "stats": { "sent": 180, "received": 178, "loss_pct": 1.11, … } }  ]}
  • Versioned contract. JSON uses schema_version: 1. Breaking changes require a new schema version.
  • Whole-run stats. stats covers every probe in the run; samples is the recent tail.
  • Private by default. Output files are written 0600, and existing files are never replaced without --overwrite.

# what pinghue is not

Small on purpose.

  • Not a Prometheus, Smokeping, Zabbix, or NMS replacement.
  • Not a long-running metrics database or alerting system.
  • Not a privileged daemon.
  • Not a packet capture or traceroute tool.
  • Not a service that accepts remote network requests.

A focused local tool for maintenance windows, migrations, and quick reachability checks. Nothing more, on purpose.
