modes

  • pinghue 1.1.1.1 8.8.8.8
  • pinghue -p 443 example.com
  • pinghue -p 443 example.com -c 3 --no-tui

icmp

The default. Concurrent echo probes to every host at once, in the full TUI with history, states, and keyboard control: r reset, R reset all, a addresses, b probe now.

tcp -p PORT

Connect checks on any port from 1 to 65535. No privileges needed. A refused connection gets its own ! marker, distinct from loss.

lines --no-tui

One line per probe for cron and CI, with fail-on-down exit codes and --output for the report.

2026-05-14T18:32:11.420000+00:00 example.com ok latency=14.08ms

one scale, every run

Latency maps to eight fixed glyphs. The scale never rescales, so a row from tonight reads the same as a row from last month. Green up to 100ms, amber above it, red for loss.

history

A host that drops one probe stays intermittent until you reset it. Three failures in a row and it is down until it answers again. The report reflects the whole run, not the last few seconds.

versioned contract
The JSON carries schema_version: 1. A breaking change requires a new schema version.
whole-run stats
stats covers every probe in the run. samples is the recent tail.
private by default
Reports are written 0600, and an existing file is never replaced without --overwrite.

what pinghue is not

  • Not a Prometheus, Smokeping, Zabbix, or NMS replacement.
  • Not a long-running metrics database or alerting system.
  • Not a privileged daemon.
  • Not a packet capture or traceroute tool.
  • Not a service that accepts remote network requests.

A small local tool for maintenance windows, migrations, and quick reachability checks. Up to 1024 concurrent probes, no server, no daemon.
